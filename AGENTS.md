# Работа с русификатором SOCOM v3.00

- Сначала читать `README.md`, `project.json` и `docs/DEVELOPMENT.md`; перед бинарными правками — `docs/TECHNICAL.md`.
- Каноническое имя репозитория — `socom-us-navy-seals-russian-patch`.
- Поддерживается только PS2 USA v3.00, SCUS-97134. Все внутренние пути задаются относительно корня репозитория.
- ISO не является частью проекта. При необходимости принимать путь к чистому английскому ISO аргументом `--input`; не добавлять и не копировать образ в репозиторий.
- Русификатор обязан собираться из чистого английского ISO без русского ISO и предыдущих сборок.
- Готовые ресурсы перевода хранить в `resources/files/`, редактируемые снимки и словари — в `sources/`.
- Корневой `install.cmd` запускает прямую сборку через `tools/project.py`. Не создавать отдельный патч, дубликат установщика или папку выпуска.
- `reports/` — временная игнорируемая область. Не коммитить её содержимое.
- Для чтения и проверок использовать `python -B`, чтобы не создавать `__pycache__`.
- Собирать ISO после готовой пачки правок. Никогда не перезаписывать существующий ISO.
- Не перерисовывать изображения карт; допустимы правки текста меню карты.
- Не переводить служебные имена, аргументы выбора предметов и пути ресурсов. Различать UI, скомпилированные подписи и HUD.
- Для RDR использовать `socom_formats.serialize`/`serialize_fit` и `rdr_runtime.runtime_roundtrip`; не объединять узлы с указателями.
- Перед сборкой проверять анимации через `animation_runtime.inspect(data, True)`. Строки `Name_Table` должны оставаться различимыми: загрузчик удаляет дубли без перенумерации индексов.
- Каждую новую правку выполнять в отдельной Git-ветке. Git хранит старые/новые байты и историю; параллельные архивы и папки пачек не создавать.
- После проверки согласованно обновлять `resources/`, `sources/`, корневой пакет и `project.json`, затем объединять ветку обычным Git-процессом.
- Перед выпуском выполнить аудит ресурсов, прямую сборку из чистого ISO, полную установку, проверку всех файлов ISO и сохранности английской озвучки.
- Не считать выборочные игровые проверки подтверждением прохождения всей игры.
- Пользовательскую память вне проекта без отдельного прямого запроса не менять.
